# AHTT Bore 模拟联调

## 核心原则

把链路拆成四段并逐段留证：`桩 → bore.pub → 本机模拟器 → AHTT协议状态机`。Bore 只转发 TCP；`0x01/0x81` 行为必须由 AHTT 模拟器和桩端日志共同证明。

详细命令、回显、时序和恢复步骤见 [运行手册](references/AHTT-Bore模拟联调运行手册.md)。

## 何时使用

- 新增或修改 AHTT 命令帧后，需要从“脚本通过”进入板端联调；
- 真实平台不能选择性不回复心跳，需要模拟 `0x81` 静默；
- 需要验证 10 秒×3、约30秒 Offline、5/10/30 秒 TCP 退避或 Bore 恢复后的重新签到；
- 用户明确指定串口（例如 `COM3`）配置临时测试域名并重启设备。

不用于真实生产平台的日常接入、充电控制、升级或任何未获用户授权的串口写入。

## 必经门禁

1. 先阅读 `ahtt-development`，并运行当前切片对应的 `tools/ahtt/Validate-AHTTM*.ps1`；失败时不得进入板端联调。
2. 运行 `tools/ahtt/test_ahtt_platform_sim.py` 和 `ahtt_platform_sim.py --selftest`。
3. 模拟器仅监听 `127.0.0.1:18888`；Bore 用 `RUST_LOG=info` 启动并从 `listening at bore.pub:<port>` 提取当前端口。端口、Bore PID、模拟器 PID和日志路径必须写入本次会话记录。
4. 用户明确指定 COM 口即构成本次会话的串口配置与重启授权。独占打开失败即停止；不得杀死用户串口工具、猜测其他 COM 口或重复盲发命令。
5. 仅当串口回显包含 `Set Plat Main domain port: "bore.pub", port= <port> ok!` 后发送 `reboot`。重启后必须以模拟器收到 `0x01` 签到为参数生效证据。

## 联调模式

| 模式 | 本机动作 | 板端通过证据 |
|---|---|---|
| 心跳静默 | 模拟器默认不回 `0x81`，TCP保持 | `0x81`约0/10/20秒三次发送，约30秒 Offline/关TCP |
| TCP退避 | 仅停止本会话保存的 Bore PID | `+QIOPEN`失败后约5/10/30/30秒重连；CFUN或模组恢复须标为网络层行为 |
| 恢复 | 同一远端端口重新启动 Bore | 新 TCP 会话的`0x01`、模拟器回复、首个`0x81` |

## 串口命令

实际设备已验证的命令格式为：

```text
set para domain:bore.pub,<当前Bore端口>
reboot
```

使用 `115200, 8N1, 无流控`；显式关闭 DTR/RTS，命令使用 `\r\n`。端口必须是当前存活 Bore 日志中的 `1..65535` 值，不能复用旧会话端口。

## 判定与回写

- 平台应答流水号独立于设备流水号；对设备请求的应答按有效等待、命令和参数合法性关联。
- 只依据已保存的桩端串口日志、模拟器日志和 Bore 日志标记通过；不把“Bore listening”当作桩已连接。
- 回写 `AHTT-板端验证清单.md`、`AHTT-联调问题记录.md`、测试向量、事实台账和命令矩阵。未完成的旧应答注入、并发 Socket、20ms任务/看门狗和充电状态必须保持待验证。

## 结束与异常

- 测试结束后固定恢复 `www.ahttcd.cn,8888`，再重启并确认。该端点是用户确认的默认历史值，执行恢复时无需再次征求同意。
- 只终止本会话创建并记录 PID 的 Bore/模拟器进程。Bore 重启后端口可能变化；若不能重新获得原端口，必须重新配置设备后再测试。
- `COM` 拒绝访问、Bore 无端口公告、模拟器未收到`0x01`、或设备未重启均为停止条件，先保留日志并定位，不得假定成功。
