# AHTT Bore 模拟联调

## 1. Skill 定位

本 Skill 负责 **AHTT Bore 模拟联调的任务路由、门禁、证据链和异常停止条件**。

以下内容不在本 Skill 重复定义：

- C 编码规范。
- Git 安全规则。
- 通用代码修改确认。
- AHTT Recv / Send / NVM 通用规则。
- Planner / Executor / Reviewer 通用 SOP。
- 具体的 PowerShell、串口和 Bore 命令全文。

上述内容分别由：

```text
AGENTS.md
docs/ai/AHTT_AI_Development_Prompts.md
ahtt-development
references/AHTT-Bore模拟联调运行手册.md
```

维护。

执行本 Skill 前必须先读取：

```text
AGENTS.md
ahtt-development
```

---

## 2. 何时使用

适用于：

- AHTT 命令帧代码和 Host 验证完成后，需要进入真实测试桩联调。
- 真实平台无法构造某种异常场景，需要本地 TCP 模拟器控制应答行为。
- 验证签到、心跳静默、Offline、断链、重连或恢复。
- 验证 TCP backoff。
- 使用 Bore 将本机模拟器临时暴露给授权测试设备。
- 经用户批准后，通过指定串口临时配置测试端点并重启设备。
- 测试结束后恢复用户已确认的原端点。

不适用于：

- 未经授权的设备。
- 生产平台常规接入。
- 与当前 AHTT 联调无关的串口写操作。
- 未经用户批准的设备配置修改或 reboot。
- 充电控制、升级、安全操作等本 Skill 未定义的业务。

---

## 3. 核心证据链

联调链路必须拆成：

```text
测试桩
→ 公网 / Bore
→ 本机 AHTT 模拟器
→ AHTT 协议状态机
```

每一段都必须有独立证据。

例如：

- Bore 正在监听，只能证明 Bore 入口存在。
- 模拟器收到连接，只能证明 TCP 已到达本机。
- 模拟器收到 AHTT 签到帧，才能证明桩端参数生效并进入协议链路。
- 桩端日志中的状态变化，才能证明 MCU 侧行为。
- 单独一侧日志不能替代完整链路证据。

---

## 4. 运行参数的唯一来源

本 Skill 不永久硬编码：

- 当前生产端点。
- 当前 Python 绝对路径。
- 当前 Bore 可执行文件路径。
- 当前 COM 口。
- 当前串口参数。
- 当前 timeout / retry 数值。
- 当前 Bore 端口。
- 当前脚本版本。

开始联调前必须读取：

```text
references/AHTT-Bore模拟联调运行手册.md
```

并结合：

- 当前代码。
- 当前 `tools/ahtt`。
- 用户本次明确提供的信息。

确认当前参数。

如果运行手册与当前代码或用户确认信息冲突：

```text
[CONFLICT]
```

不得静默使用历史值。

## 5. 联调前置门禁

进入真实板端联调前必须满足：

### 5.1 当前任务已有明确目标

必须明确：

- 测试什么。
- 使用哪台测试设备。
- 需要验证的协议行为。
- 期望的成功 / 失败证据。

### 5.2 Host 侧验证已经通过

按当前 `AGENTS.md` 和已批准 Plan 执行当前切片适用的：

- validation script。
- Python test。
- simulator selftest。
- 必要的 build。

任何与本次联调直接相关的 Host 门禁失败：

```text
STOP
HOST-GATE-FAILED
```

不得绕过 Host 失败直接进入板端。

### 5.3 测试设备已获授权

必须确认当前目标是用户允许操作的测试设备。

如果设备授权不明确：

```text
STOP
DEVICE-AUTH-UNKNOWN
```

## 6. 串口配置与 reboot 授权

仅“知道一个 COM 口”不等于获得设备写入和 reboot 授权。

允许临时配置测试端点并重启设备，必须同时满足：

1. 用户明确要求执行本次 Bore 板端联调。
2. 用户明确指定或确认目标测试设备 / COM 口。
3. 当前已批准联调方案包含临时端点配置和必要的 reboot。

满足后，本次联调范围内可以按运行手册执行。

如果 COM 口被占用：

- 停止。
- 不杀死用户现有串口工具。
- 不猜测其他 COM 口。
- 不向其他串口盲发命令。

## 7. 启动模拟器与 Bore

具体命令、日志目录、端口提取和进程管理步骤统一读取：

```text
references/AHTT-Bore模拟联调运行手册.md
```

执行时必须记录本次会话真实产生的：

```text
模拟器 PID
Bore PID
Bore 远端端口
模拟器日志
Bore stdout / stderr
串口脱敏摘要
固件版本

测试时间
```

只允许操作本次会话自己创建并记录的进程。

不得因为历史会话曾使用某个端口，就复用旧 Bore 端口。

---

## 8. 临时测试端点配置

只有在：

```text
模拟器存活
Bore 存活
远端端口有效
设备写入已获授权
```

全部满足后，才允许按运行手册临时修改测试桩的平台端点。

配置成功必须以：

```text
设备串口成功回显
+
模拟器收到新 TCP 连接 / AHTT 签到
```

作为证据。

只有命令发送成功、只有 Bore listening 或只有串口无报错，都不能单独判定配置生效。

---

## 9. 联调模式

### 9.1 心跳静默

目标：

验证平台不回复心跳时，桩端的：

- 心跳发送。
- 等待。
- 重试。
- 超时。
- Offline / 断链。
- 清理。

具体次数和时间基线从当前代码、Plan 和运行手册确认。

不得只因为历史 Skill 中曾记录某组秒数就直接当成当前要求。

### 9.2 TCP backoff

目标：

验证外部链路不可达时：

- TCP open 失败。
- 退避。
- 重试。
- 网络层恢复。

Bore 只用于构造当前测试需要的链路条件。

如果观察到 CFUN、模组复位、掉电等行为：

- 区分协议层与网络 / 模组层。
- 不把所有现象归因于 AHTT 状态机。

### 9.3 Bore 恢复

目标：

验证链路恢复后：

- 新 TCP 连接建立。
- AHTT 重新签到。
- 正常业务恢复。
- 旧等待态不会污染新会话。

如果无法恢复原 Bore 端口：

- 停止使用旧端口假设。
- 按当前运行手册重新建立有效端口。
- 如需重新配置设备，确保仍在本次已批准联调范围内。

## 10. 停止条件

出现以下任一情况，应停止扩大操作范围并保留证据：

```text
Host gate 失败
目标设备授权不明确
COM 拒绝访问
Bore 未产生有效远端端口
模拟器未成功运行
设备配置没有明确成功回显
设备 reboot 行为无法确认
模拟器未收到预期签到
日志证据互相矛盾
运行手册与当前代码发生关键冲突
需要操作计划外设备 / 端口 / 进程
```

停止后输出：

- 已完成步骤。
- 当前日志位置。
- 最后一个确定成功的门禁。
- 失败点。
- 下一步需要的用户决策或代码分析。

不得假定成功后继续。

---

## 11. 日志与隐私

联调日志只保存完成当前诊断所需的信息。

不得主动记录或传播：

- 密钥。
- 密码。
- 完整敏感配置输出。
- 与当前测试无关的设备私密信息。

如命令输出可能包含敏感字段：

- 只保留与当前判断相关的脱敏摘要。
- 不把完整配置 dump 写入长期文档。

---

## 12. 判定原则

通过结论必须来自对应证据层。

区分：

```text
Host
Simulator
Bore
Serial / Board log
Board behavior
Real platform
```

示例：

```text
Bore listening
≠ 桩已连接

Simulator connected
≠ AHTT 签到完成

AHTT 0x01 收到并正确应答
≠ 心跳超时行为已验证

Host test PASS
≠ Board PASS
```

最终状态标签继续遵守项目 `AGENTS.md`。

---

## 13. 测试结束与恢复

测试开始前，应在用户批准的联调方案中明确：

- 本次会临时修改哪个设备的测试端点。
- 测试结束必须恢复什么已确认配置。
- 恢复后需要 reboot 还是其他动作。

如果恢复动作已经包含在用户批准的联调方案内：

- 测试结束可直接执行该恢复步骤。
- 不需要为了同一恢复步骤再次重复确认。

恢复目标必须来自：

- 用户本次确认。
- 当前权威配置。
- 当前运行手册经过核对的值。

不得因为 Skill 中记录了历史生产地址，就假设该地址永久有效。

恢复后必须取得足够证据确认设备已离开测试端点。

---

## 14. 进程清理

结束测试时：

- 只终止本次会话明确记录的 Bore PID。
- 只终止本次会话明确记录的模拟器 PID。
- 不按进程名批量杀进程。
- 不结束用户已经存在的调试 / 串口工具。
- 不删除与当前会话无关的日志。

## 15. 文档回写

根据本次实际证据判断是否更新：

```text
AHTT-板端验证清单.md
AHTT-联调问题记录.md
AHTT-报文测试向量.md
AHTT-V3.12-事实台账.md
AHTT-V3.12-命令追踪矩阵.md
```

只把实际取得证据的内容标为通过。

仍未验证的：

- 并发 Socket。
- 任务时序。
- 看门狗。
- 充电业务。
- 真实平台行为。
- 其他未进入本次测试范围的项目。

必须保持未验证状态。

## 16. 与 AHTT 主工作流的关系

如果当前任务处于 Planner 阶段：

- 只设计 Bore 验证方案。
- 不执行真实串口写入、reboot 或进程操作。

如果处于 Executor 阶段且 Plan 已批准：

- 只执行 Plan 已批准的联调范围。
- 出现计划外设备、端口、操作或风险时返回 Planner / 用户确认。

如果处于 Reviewer 阶段：

- 只审查联调证据和结论。
- 不为了补证据自动操作设备。

角色边界以：

```text
docs/ai/AHTT_AI_Development_Prompts.md
```

为准。
